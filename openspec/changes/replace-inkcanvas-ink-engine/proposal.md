## Why

WindBoard 当前的笔迹依赖 `InkCanvas`（WPF Ink），在“笔迹数量巨大 + 频繁缩放/拖动”场景下容易出现：

- 视图缩放/平移时 `InkCanvas`/WPF 需要反复遍历并栅格化大量 `Stroke`，CPU 占用高、帧率下降
- `StrokeCollection` 与 `DrawingAttributes` 的资源管理不可控（内存抖动/峰值高），且很难做分层缓存与可见性裁剪
- 书写时（尤其是高采样压感笔）对 UI 线程压力大，容易出现卡顿与延迟
- 后续想对墨迹做“处理/分析/重渲染”（分段、识别、形状矫正、回放等）会被 `System.Windows.Ink` 的数据结构和行为绑定

本变更的目标是：**重写墨迹引擎，彻底摆脱对 `InkCanvas` 的依赖**，采用 DirectX 路线进行渲染与资源管理，同时保留可扩展的数据模型与编辑管线。

## What Changes

- 新增：自研 `InkDocument` 数据模型（点/笔划/片段/空间索引/撤销重做），支持“任意部位擦除”（擦断分段）
- 新增：DirectX 渲染层（基于 `Vortice.Windows`，D3D11 + D2D1）输出到 WPF（`D3DImage`），支持海量笔迹下的可见性裁剪与分层缓存
- 新增：WBI v2 笔迹存储格式（允许引入新笔迹），并提供从旧 `.isf` 的导入迁移
- 新增：两套线宽语义并可切换（视图固定粗细 / 内容固定粗细），且该语义可随笔迹或工具一起保存
- 重写：与书写相关的设置（平滑、笔锋/压感、粗细等）先从现有架构中完全移除，再以新模型重建，避免旧逻辑残留导致的不一致/难以修复问题
- 移除：对 `InkCanvas` 的依赖（UI、模式、服务、导入导出、预览/导出渲染等全链路替换）

## Non-Goals

- 不追求与 WPF Ink 的内部实现一致（例如 ISF 细节、像素级“完全同一张图”）；新引擎以“几何保真 + 观感一致”为目标，并对远景 LOD 设定清晰的误差边界
- 不引入跨平台 UI（仍然是 Windows + WPF）
- 不在本变更中一次性引入高级“墨迹语义处理”（识别/矫正/形状库），但会预留扩展点

## Success Criteria

- 在“笔迹数量/点数极大”的页面上，缩放/拖动保持稳定帧率（目标 60fps，允许在极端硬件下自适应降级）
- 书写延迟显著降低：高采样压感笔输入不会造成明显 GC 抖动；live stroke 跟手
- 两套线宽语义可用且可切换：在缩放/导出/重载后保持一致（视图固定粗细 / 内容固定粗细）
- 放大查看小字/连笔/精细笔画时，默认质量策略不丢失细节（任何点简化仅允许在远景 LOD 且有误差阈值）
- 支持任意擦除并产生分段（可撤销/重做），选择/移动/缩放/复制/置顶/删除等基础编辑能力可用
- WBI v2 可完整保存/还原页面内容；旧 WBI（含 `.isf`）可导入到新模型

## Impact

- **破坏性变更**：页面笔迹模型与 WBI 格式升级；与 `System.Windows.Ink` 绑定的代码将被替换
- UI 与交互：选择框/拖拽/缩放等需要自研替代 `InkCanvas` 的 Selection 行为
- 导出与缩略图：需要改为使用新渲染器（或离屏渲染路径）生成位图

## Risks / Mitigations

- DirectX/WPF 互操作复杂（`D3DImage`、设备丢失、DPI、共享纹理）：提供明确的设备生命周期与恢复策略，并用隔离层封装
- 新擦除/选择算法的性能与边界：引入空间索引（网格/四叉树）与分段数据结构；优先保证交互正确性，再做性能优化
- 迁移成本：先提供“导入旧 `.isf`”与“新格式保存”，必要时保留可选的旧格式导出（可后续决定）
