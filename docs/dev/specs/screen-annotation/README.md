# 屏幕批注模式实现规格

## 1. 文档目的

本文档用于规定 WindBoard“屏幕批注模式（Screen Annotation）”首版的实现边界、模块结构与关键交互约束。

本文档已定案采用以下实现路线：

- 复用现有 `BoardCanvasControl`、输入控制器与渲染内核；
- 新增一个透明顶层批注层窗口；
- 新增一个独立悬浮工具栏窗口；
- 通过 Win32 窗口样式切换实现点击穿透。

本文档不承担方案比选功能，不再讨论其它替代路线。

## 2. 功能背景

屏幕批注模式用于让用户在最小化或隐藏主窗口后，直接在桌面或任意应用界面上进行临时书写批注。进入该模式后，系统需要提供两类顶层窗口：

- 一个铺满目标显示器的透明批注层窗口；
- 一个独立悬浮的工具栏窗口。

工具栏首版固定提供以下能力：

- 标志按钮：拖动悬浮条，控制右侧工具按钮显隐；
- 书写；
- 擦除；
- 穿透；
- 回到软件。

该模式的核心体验是：

- 穿透模式下，批注层继续可见，但底层桌面或应用接收输入；
- 书写和擦除模式下，批注层重新接管输入；
- 用户可随时通过工具栏回到主程序。

## 3. 最终方案概述

WindBoard 首版屏幕批注模式固定采用“复用现有白板内核 + 新增桌面模式壳层”的实现方式。

整体结构如下：

- 主窗口负责进入与恢复；
- 桌面模式控制器负责批注层窗口、工具栏窗口、模式切换和异常清理；
- 批注层窗口内部承载现有 `BoardCanvasControl`；
- 工具栏窗口独立存在，避免在穿透模式下失去可操作性；
- 穿透行为由窗口级命中测试控制，不复用现有白板的 `BoardTool.Select` 语义。

这一路线是首版唯一实现方案。

## 4. 首版目标与非目标

### 4.1 首版目标

- 在当前进程内实现屏幕批注模式，不引入独立 helper 进程。
- 最大化复用现有 `BoardCanvasControl`、`BoardInputController`、`BoardSession`、渲染器与笔迹/橡皮逻辑。
- 进入屏幕批注模式后，仅针对一个目标显示器创建一套批注层窗口与悬浮工具栏窗口。
- 支持以下模式切换：
  - `PassThrough`
  - `Pen`
  - `Eraser`
- 支持从桌面模式一键恢复主窗口。
- 为关键流程补齐日志与错误处理，避免进入或退出失败后留下顶置幽灵窗口。

### 4.2 首版非目标

- 不支持所有显示器同时铺满并联动书写。
- 不支持桌面模式下的多页管理。
- 不支持导入图片、文本、文件等元素到桌面批注层。
- 不支持将桌面批注内容自动并回主白板工作区。
- 不支持复用现有选择模式的框选、移动、缩放语义。
- 不处理复杂的全屏独占应用兼容性问题。

## 5. 现有基础与实现缺口

### 5.1 可直接复用的基础能力

当前仓库已经具备桌面批注模式所需的大部分核心基础：

1. 画布控件已独立封装  
   `WindBoard/Controls/BoardCanvasControl.xaml.cs`

- 当前画布控件内部已经封装：
  - `BoardSession`
  - `BoardViewport`
  - `BoardSceneRenderer`
  - `BoardInputController`
- 同时暴露 `Tool`、`PenColor`、`PenBaseSize`、`Eraser`、`CanvasBackgroundColor` 等入口。
- 屏幕批注模式不需要重写新的笔迹控件，只需将现有控件放入新的顶层窗口中。

2. 输入控制器已支持笔、鼠标、触控  
   `WindBoard/Interaction/BoardInputController/BoardInputController.cs`

- 已实现：
  - 书写
  - 擦除
  - 视口平移/缩放
  - 选择相关逻辑
  - 脏区重绘
- 屏幕批注模式首版真正复用的是：
  - 书写
  - 擦除
  - 指针捕获与释放
  - 脏区刷新

3. 渲染链具备透明背景能力  
   `WindBoard/Rendering/DxSwapChainPanelRenderer.cs`

- 当前交换链使用 `Premultiplied Alpha`。
- 渲染器支持 `ClearColor`，可以将画布背景清为透明色。
- 这为透明批注层窗口提供了渲染基础。

4. 应用已具备多窗口与 Win32 互操作基础  
   相关文件：

- `WindBoard/MainWindow.xaml.cs`
- `WindBoard/UI/MainWindow/MainWindow.WindowMode.cs`
- `WindBoard/App.xaml.cs`

当前代码已经有：

- 通过 `new SettingsWindow()` 创建额外窗口的先例；
- 通过 `WindowNative.GetWindowHandle(this)` 获取 `HWND`；
- 通过 `AppWindow.GetFromWindowId(...)` 获取 `AppWindow`；
- 通过 Win32 `ShowWindow` 兜底最小化主窗口的实现。

这意味着：

- 新增桌面批注窗口和桌面工具栏窗口在现有架构中是自然延伸；
- 实现点击穿透、TopMost、工具窗口等需求时，已有 `HWND` 级操作基础。

### 5.2 当前实现缺口

当前项目距离屏幕批注模式仍缺以下能力：

1. 缺少统一的桌面模式功能层

- 当前没有单独的 `Flow/Controller` 管理：
  - 进入桌面模式
  - 创建窗口
  - 切换输入模式
  - 恢复主窗口
  - 退出桌面模式

2. 缺少点击穿透原生封装

- 当前仓库内尚未看到对 `WS_EX_TRANSPARENT`、`SetWindowLongPtr`、`SetWindowPos(HWND_TOPMOST)` 等操作的统一封装。
- 这部分必须新增专用 interop/helper。

3. 现有 `BoardTool.Select` 语义不等于“穿透模式”

- 当前 `BoardTool.Select` 的语义是画板内选择和浏览，而不是将窗口输入穿透到底层应用。
- 屏幕批注模式必须新增一层外部模式状态，与 `BoardTool` 解耦。

4. 缺少目标显示器解析与铺屏逻辑

- 当前仓库没有现成的“进入桌面模式时锁定目标显示器矩形”的服务层。
- 需要补齐：
  - 目标显示器选择
  - 批注层铺满显示器
  - 工具栏初始位置计算
  - 显示器变化后的恢复策略

5. 主窗口默认使用 `MicaBackdrop`

- 当前主窗口与设置窗口都配置了 `MicaBackdrop`。
- 屏幕批注层窗口不能沿用该外观，否则无法得到真正透明的批注层。

## 6. 首版范围裁剪

为了保证首版范围可控，屏幕批注模式固定收敛为以下行为。

### 6.1 会话模型

- 使用独立的 `BoardSession`；
- 只保留一个页面；
- 会话仅驻留内存；
- 退出屏幕批注模式时直接销毁，不与主白板合并。

### 6.2 工具模型

- 桌面模式仅暴露：
  - 穿透
  - 书写
  - 擦除
- 不暴露：
  - 画板选择
  - 页面切换
  - 导入导出
  - 元素编辑

### 6.3 显示器模型

- 首版仅对进入模式时锁定的一个显示器生效；
- 工具栏只在该显示器范围内活动；
- 不做跨屏联动。

## 7. 最终架构

新增 `Features/ScreenAnnotation/` 目录，并按职责拆分如下：

```text
WindBoard/Features/ScreenAnnotation/
  Models/
    ScreenAnnotationMode.cs
    ScreenAnnotationStartOptions.cs
    ScreenAnnotationDisplayTarget.cs
  Services/
    ScreenAnnotationFlow.cs
    ScreenAnnotationSessionHost.cs
    ScreenAnnotationDisplayResolver.cs
    ScreenAnnotationWindowInterop.cs
    ScreenAnnotationWindowState.cs
  UI/
    ScreenAnnotationWindow.xaml
    ScreenAnnotationWindow.xaml.cs
    ScreenAnnotationToolbarWindow.xaml
    ScreenAnnotationToolbarWindow.xaml.cs
```

### 7.1 `ScreenAnnotationFlow`

职责：

- 作为桌面模式总控；
- 接收来自主窗口的“进入屏幕批注模式”请求；
- 解析目标显示器；
- 创建、显示与回收批注层窗口和工具栏窗口；
- 切换桌面模式输入状态；
- 在退出时恢复主窗口。

约束：

- `MainWindow` 中只保留一个薄入口，不把桌面模式流程直接塞进主窗口 code-behind。

### 7.2 `ScreenAnnotationWindow`

职责：

- 作为真正的批注层窗口；
- 内部承载一个 `BoardCanvasControl`；
- 负责铺满目标显示器；
- 负责与 `ScreenAnnotationWindowInterop` 配合切换“接管输入 / 点击穿透”。

### 7.3 `ScreenAnnotationToolbarWindow`

职责：

- 展示桌面模式悬浮工具栏；
- 始终保持可交互；
- 提供拖动、展开/收起、模式切换和回到软件。

### 7.4 `ScreenAnnotationWindowInterop`

职责：

- 对 `HWND` 层操作做统一封装；
- 提供以下能力：
  - 置顶
  - 点击穿透开/关
  - 工具窗口样式设置
  - 必要时触发窗口样式刷新

约束：

- 该层只做原生互操作，不承载业务状态机。

### 7.5 `ScreenAnnotationDisplayResolver`

职责：

- 解析进入桌面模式时的目标显示器；
- 返回显示器边界矩形；
- 为工具栏初始位置提供约束信息。

### 7.6 `ScreenAnnotationSessionHost`

职责：

- 托管桌面模式对应的 `BoardSession` 与 `BoardCanvasControl` 初始化参数；
- 统一设置桌面模式下的默认画笔、橡皮和透明背景；
- 统一初始化桌面批注使用的视口。

## 8. 输入模式设计

### 8.1 屏幕批注模式状态

新增：

```text
ScreenAnnotationMode
- PassThrough
- Pen
- Eraser
```

该模式与现有 `BoardTool` 的关系如下：

| 屏幕批注模式 | 批注层窗口命中 | `BoardCanvas` 内部工具 |
| --- | --- | --- |
| `PassThrough` | 穿透 | 保留上次绘图工具或不关心 |
| `Pen` | 接管输入 | `BoardTool.Pen` |
| `Eraser` | 接管输入 | `BoardTool.Eraser` |

### 8.2 状态语义约束

- `PassThrough` 不是 `BoardTool.Select`；
- `PassThrough` 是窗口级命中测试状态；
- `Pen` 和 `Eraser` 才映射到现有白板内部工具。

### 8.3 不复用 `BoardTool.Select` 的原因

当前 `BoardTool.Select` 已绑定以下语义：

- 框选
- 移动选中对象
- 视口平移
- 选择覆盖层更新

如果桌面模式直接把“穿透”映射到 `Select`，会产生以下问题：

- 批注层依旧会接管输入，而不是穿透到底层应用；
- 选择框和选择 Dock 可能误显示；
- 桌面模式语义和现有白板语义发生混淆。

因此屏幕批注模式必须彻底绕开 `Select`。

## 9. 视口与坐标设计

### 9.1 目标

桌面批注层的书写坐标必须尽量与屏幕坐标一致，避免“看起来写在屏幕上，实际却落在可平移无限画布中心附近”。

### 9.2 固定视口方案

桌面模式下将视口固定为“屏幕坐标近似恒等映射”：

- `Zoom = 1`
- `CameraWorld = ViewportCenterDip`

原因：

- 当前 `BoardViewport` 的世界到屏幕变换为：
  - `Translate(-CameraWorld) * Scale(Zoom) * Translate(ViewportCenterDip)`
- 当 `Zoom = 1` 且 `CameraWorld = ViewportCenterDip` 时，世界坐标与屏幕坐标可以近似重合。

这样做的结果是：

- 指针所在屏幕位置与笔迹落点更直观；
- 不需要在首版引入新的屏幕坐标系类型；
- 对现有渲染与命中逻辑的冲击最小。

### 9.3 固定视口约束

- 屏幕批注模式下禁用平移和缩放手势；
- 不暴露页面切换；
- 不暴露选择和框选；
- 桌面模式固定为“一页、固定视口”的批注层。

## 10. 窗口模型设计

### 10.1 窗口组成

进入屏幕批注模式后创建两个顶层窗口：

1. `ScreenAnnotationWindow`

- 全屏铺满目标显示器；
- 透明背景；
- 默认置顶；
- 不显示在任务栏；
- 仅承担批注层职责。

2. `ScreenAnnotationToolbarWindow`

- 小尺寸悬浮窗口；
- 独立于批注层窗口；
- 始终保留可点击区域；
- 可拖动；
- 可折叠右侧工具区；
- “回到软件”按钮负责恢复主窗口并退出桌面模式。

### 10.2 工具栏必须独立窗口

若把工具栏放进批注层窗口内部，会产生以下问题：

- 批注层切到穿透模式后，工具栏也会一起穿透，导致无法再切回书写；
- 需要在窗口内部做复杂的局部命中测试例外；
- 行为比独立工具栏窗口更难维护。

因此首版固定如下：

- 批注层窗口负责“铺满屏幕 + 可穿透”；
- 工具栏窗口负责“始终可操作”。

### 10.3 透明与顶置要求

桌面批注窗口必须满足：

- XAML 内容树背景透明；
- 移除 `MicaBackdrop` 等系统背景；
- 渲染器清屏色使用透明；
- 通过 `HWND` 保证窗口置顶。

首版实现前必须先做技术样机，验证当前运行环境下 WinUI 3 顶层窗口能否稳定获得真正透明的视觉效果。

## 11. 点击穿透设计

### 11.1 实现方式

通过 `HWND` 扩展样式切换实现：

- 穿透模式：
  - 打开 `WS_EX_TRANSPARENT`
- 书写和擦除模式：
  - 关闭 `WS_EX_TRANSPARENT`

并配合：

- `SetWindowLongPtr`
- `SetWindowPos(..., HWND_TOPMOST, ..., SWP_FRAMECHANGED | SWP_NOMOVE | SWP_NOSIZE)`

确保样式切换及时生效。

### 11.2 行为约束

- `PassThrough`
  - 窗口继续可见；
  - 底层桌面或应用接收输入。
- `Pen` / `Eraser`
  - 批注层接管输入；
  - 由现有 `BoardInputController` 处理书写和擦除。

### 11.3 首版重点验证项

以下场景必须优先验证：

- 鼠标是否稳定穿透到底层窗口；
- 触控笔是否在切换模式后仍能正常开始笔划；
- 触摸在透明顶层窗口上的行为是否与鼠标一致；
- 模式切换瞬间是否存在输入状态残留。

首版优先保证：

- 鼠标
- 触控笔

触摸作为第二优先级验证项处理。

## 12. 进入与退出流程

### 12.1 进入桌面模式

流程固定如下：

1. 用户从主窗口触发“进入屏幕批注”；
2. `ScreenAnnotationFlow.Start(...)` 执行；
3. 解析目标显示器；
4. 创建桌面批注会话与批注层窗口；
5. 创建悬浮工具栏窗口；
6. 将批注层铺满目标显示器并置顶；
7. 工具栏移动到默认位置；
8. 主窗口最小化；
9. 默认进入 `PassThrough`。

进入后默认使用 `PassThrough`，避免刚进入模式就立即抢占所有鼠标操作。

### 12.2 退出桌面模式

流程固定如下：

1. 用户点击“回到软件”；
2. `ScreenAnnotationFlow.Stop(...)` 执行；
3. 关闭批注层窗口；
4. 关闭工具栏窗口；
5. 恢复主窗口；
6. 激活主窗口；
7. 释放桌面批注会话。

### 12.3 失败兜底

若中途任一步失败，必须遵循以下原则：

- 优先恢复主窗口；
- 已创建的桌面窗口尽量回收；
- 记录错误日志；
- 避免留下不可见但仍顶置的幽灵窗口。

## 13. 目标显示器策略

### 13.1 首版固定策略

首版固定以“进入模式时主窗口所在显示器”为目标显示器。

原因：

- 行为稳定、可预测；
- 与当前“从主窗口触发进入桌面模式”的交互一致；
- 比“跟随鼠标所在屏幕”更容易复现和排障。

### 13.2 不属于首版的扩展

以下扩展不属于首版，也不纳入本文档实现范围：

- 跟随鼠标所在显示器；
- 用户显式选择显示器；
- 多显示器同时铺屏。

## 14. 工具栏 UI 约束

### 14.1 首版按钮集合

工具栏首版只保留以下按钮：

- 标志按钮
- 书写
- 擦除
- 穿透
- 回到软件

### 14.2 首版交互行为

- 标志按钮拖动整个悬浮条；
- 再次点击标志按钮可折叠或展开右侧工具区；
- `PassThrough` 作为默认选中态；
- `Pen`、`Eraser` 切换时同步更新按钮高亮状态；
- “回到软件”按钮优先保证可靠恢复主窗口，视觉效果次之。

### 14.3 不属于首版的工具栏能力

以下能力不纳入首版：

- 颜色面板
- 线宽面板
- 清空全部
- 撤销/重做
- 选择

## 15. 日志与错误处理要求

考虑到桌面模式涉及多窗口与 `HWND` 操作，必须补齐日志。

日志分类固定为：

- `ScreenAnnotation`
- `ScreenAnnotation.Interop`
- `ScreenAnnotation.Display`

至少记录以下事件：

- 进入桌面模式开始、成功、失败；
- 目标显示器信息与窗口 bounds；
- 模式切换：`PassThrough -> Pen -> Eraser`；
- 原生样式切换失败；
- 主窗口恢复失败；
- 桌面窗口关闭或回收异常。

错误处理原则：

- 关键路径必须有日志；
- 原生互操作失败必须捕获异常并输出上下文；
- 不允许模式切换异常直接冒泡导致 UI 线程崩溃。

## 16. 测试与验证要求

### 16.1 首轮人工验证清单

1. 进入桌面模式后：

- 主窗口成功最小化；
- 批注层出现在正确显示器；
- 工具栏可见且可拖动。

2. 穿透模式：

- 鼠标可以点击到底层应用；
- 工具栏仍可点击。

3. 书写模式：

- 鼠标或笔可正常书写；
- 模式切回穿透后不再截获输入。

4. 擦除模式：

- 可擦除刚写出的笔迹；
- 切换模式无残留捕获。

5. 回到软件：

- 批注层关闭；
- 工具栏关闭；
- 主窗口恢复并激活。

### 16.2 单元测试重点

首版优先为纯逻辑部分补单测：

- `ScreenAnnotationMode` 状态转换；
- 显示器目标解析逻辑；
- 会话启动参数归一化逻辑；
- 桌面模式失败清理顺序。

### 16.3 暂不纳入首版的自动化验证

以下验证暂不纳入首版自动化范围：

- WinUI 顶层透明窗口 UI 自动化；
- 真实桌面上的点击穿透自动化验证。

## 17. 风险与前置验证

### 17.1 实施前必须完成的技术验证

在正式进入实现前，必须先做 3 个最小样机验证：

1. WinUI 3 顶层窗口的真实透明效果  
   目标：确认桌面批注窗口在当前运行环境中可稳定显示为透明批注层。

2. `WS_EX_TRANSPARENT` 切换是否满足预期  
   目标：确认窗口在“保持可见”的同时，鼠标确实可以穿透到底层应用。

3. 触控笔在模式切换后的连续性  
   目标：确认从穿透切回书写时不会出现“第一笔丢失”或指针捕获异常。

### 17.2 已知风险

- WinUI 3 透明顶层窗口在不同系统和驱动组合下可能有兼容性差异。
- 多 DPI 或多显示器切换时，工具栏与批注层坐标可能出现偏移。
- 若窗口样式切换或恢复流程异常，可能留下顶置窗口未释放。

### 阶段 1：技术样机

## 19. 定案结论

WindBoard 首版屏幕批注模式按以下原则实现：

- 复用现有白板内核，不重写笔迹引擎；
- 新增桌面模式壳层，而不是改造主窗口承担全部职责；
- 将“穿透模式”定义为窗口级状态，而不是复用 `BoardTool.Select`；
- 首版严格收敛范围：单显示器、单页面、内存态会话、仅保留 5 个核心按钮。

首版工作的关键不在笔迹引擎，而在：

- 透明顶层窗口；
- 点击穿透；
- 模式切换与失败恢复。

这三项验证通过后，后续实现工作整体可控。
